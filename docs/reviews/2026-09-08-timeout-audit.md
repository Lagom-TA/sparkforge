# 部署超时与可靠性审查

审查日期：2026-09-08。基线：main / f3f81dd，开始时工作区干净。范围：生成请求、Lambda 入口、任务与版本持久化、AI 输入处理；不是全仓安全认证。没有修改运行代码或部署。

## 结论

用户提供的 120-second Proxy Read Timeout 表示代理已连接源站，但未及时取得响应。当前代码存在明确的超时设计冲突：`app/frontend/src/lib/generation.ts:62` 使用非流式请求、等待 180 秒；`app/backend/routers/aihub.py:155` 等待模型完整结果。生成超过代理期限即可触发此类错误。尚缺本次请求 URL、时间、Ray ID 和线上日志，不能把具体失败请求归因视为已闭环。

仓库 `docs/e2e/2026-09-06-production.md` 已记录同类 120 秒超时、流式尝试失败及最终回退。该历史记录不代表当前线上版本已核验。

## 按优先级列出的问题

### P1：完整生成占用一个长 HTTP 请求

- 位置：`app/frontend/src/lib/generation.ts:62`；`app/backend/services/aihub.py:109`；`app/backend/routers/aihub.py:155`。
- 前端 180 秒不能延长代理的 120 秒；非流式服务没有应用级总截止时间，客户端也未显式配置 SDK timeout/max_retries。
- 影响：慢生成必然面临断连；浏览器失败不等于上游停止。重新点击可能重复消耗资源。
- 修复：持久化任务后快速返回 202 和任务 ID，由可靠队列/独立 worker 执行，浏览器用短请求查询；上游配置总预算、有限重试和幂等策略。仅把等待改成 90 秒属于止损，会更早失败，不是长生成的根治。

### P1：不能把 SSE 心跳视为当前部署的可靠解法

- 位置：`app/backend/lambda_handler.py:218,339-351`；`app/backend/routers/aihub.py:137-152`。
- 源码入口通过同步 Mangum 调用取得完整返回对象，没有实现 Lambda 原生响应流式传输。路由产生 SSE 不足以证明浏览器能实时收到心跳。
- 当前线上实际入口和代理是否缓冲待核验；历史记录也没有证明 SSE 成功。
- 验收必须测部署入口的首字节与逐块到达时间，不能只测试本地 ASGI 的第一个 yield。

### P1：停止与并发保护只在当前浏览器内生效

- 位置：`app/frontend/src/lib/generation.ts:100-104`；`app/backend/services/generations.py:163,270-282`。
- 本地 controls/isCurrent 检查无法约束另一标签页；后端更新只核验归属，未检查预期旧状态、执行者令牌或终态不可逆约束，创建也没有单项目活跃任务互斥。
- 影响：一个页面停止后，另一个页面仍可更新状态、保存迟到结果；刷新后无法由服务端接管原生成流程。
- 修复：服务端任务状态机、条件更新、执行租约/令牌、取消标记、幂等任务创建；提交产物前再次核验执行权。

### P1：版本落库、任务成功、项目激活不是同一事务

- 位置：`app/frontend/src/lib/generation.ts:269-286`；`app/frontend/src/pages/Workspace.tsx:253`；`app/backend/models/versions.py:9-14`。
- 三步分别调用接口；第二或第三步断网会留下已保存但未激活的版本，甚至把已产出任务标为失败。版本号来自浏览器，模型和现有迁移没有 `(project_id, version_number)` 唯一约束。
- 影响：双页面可创建同号版本；重试后可能重复产物或互相覆盖激活版本。
- 修复：服务端事务内分配版本号、保存产物、结束任务并激活项目；数据库唯一约束及幂等完成操作。

### P1：AI 媒体输入可触发任意本地文件读取与任意 URL 下载

- 位置：`app/backend/services/aihub.py:315-322,375-408,883-886`。
- 已登录调用方可以把绝对路径传给转录接口，后端直接 `read_bytes()` 并准备上传上游；图片/音频 HTTP URL 缺少目标地址限制和下载大小上限。
- 影响：服务端文件可能被发送至模型提供方；可请求内网地址，下载过大响应可能耗尽内存。未进行真实文件外传或内网探测，不能断言已发生泄露。
- 修复：公开 API 禁用本地路径；优先使用有归属校验的存储对象 ID。确需 URL 时限制协议、目标地址及 DNS 解析结果，流式限量读取，设置总时限。

### P2：视频生成在请求中无限轮询

- 位置：`app/backend/services/aihub.py:802-808`。
- queued/in_progress 没有最大轮询时间或次数。该接口虽非当前主生成路径，已对登录用户开放。
- 修复：任务化并返回 provider job ID 的服务端映射，限制总运行时间及轮询频率，处理未知终态。

## 修复实现（2026-09-08）

- 新增 generation_jobs：先返回 202，再以显式短 POST 执行规划、应用结构、源码三个步骤。模型阶段 70 秒截止，执行接口 85 秒截止，客户端 95 秒；未验证队列能力前不使用响应后的后台任务。这是可恢复的分步执行，不承诺关闭所有页面后自动继续后续步骤。
- 项目行锁串行化任务准入和提交，95 秒租约恢复崩溃步骤；执行令牌拦截停止、暂停后迟到结果。模型调用期间释放数据库事务。
- 幂等键绑定请求内容；版本号由服务端分配，产物/任务/项目激活在同一事务保存。旧 generation/version 写接口拒绝写入，项目执行状态不再允许客户端修改。
- 新迁移增加任务表与版本号唯一索引；遇到旧重复版本直接失败，不删除用户版本。发布需验证迁移已应用。
- 媒体只接受有大小限制的 base64 上传，禁止本地路径与任意 URL；图片数量限制 1–4。所有通用 AI 路由总预算 75 秒，关闭客户端；视频轮询受同一总预算约束。
- 新源码阶段只生成下载用的独立演示源码；平台实际预览继续使用经过校验的 AppSpec 与云端 CRUD。不会在平台执行任意模型源码。
