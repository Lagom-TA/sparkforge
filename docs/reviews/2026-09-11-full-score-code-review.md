## P1：旧标签页批准可替代最新蓝图

位置：app/backend/services/generation_jobs.py:73-95；app/backend/routers/generation_jobs.py:14-19。

保存草稿检查 expected_generation_id 和 expected_active_version_id，但 build 入口没有同等前置条件，也不要求绑定被批准的草稿。另一标签页已保存新蓝图后，旧页面携带旧 product_spec 和新 request_key 发起 build，后端终止最新 awaiting_approval 草稿，并启动旧内容的构建。新草稿仍留在历史数据中，但不再作为当前待批准蓝图恢复。

真实隔离 PostgreSQL 复现：保存“任务管理”草稿，保存“用户已保存的新蓝图”，用原蓝图发起构建；返回构建标题“任务管理”，最新草稿状态变成 stopped。保护断言失败。

修复要求：批准绑定具体 generation 与活动版本，在项目锁内校验最新状态/内容；过期批准返回409且不终止新草稿。重复请求仍幂等。补双标签页和并发批准测试。

## P1：导出 CRUD 在读取存档失败后允许覆盖原数据

位置：app/backend/services/source_export.py:17-21、31-32。

localStorage读取或JSON解析失败被静默当作空记录，随后仍允许新增保存。下一次setItem成功时，空集合加新记录整体覆盖同一存储键，造成原存档丢失。此问题发生在下载工程，不是已加读取保护的云端HTML预览。

真实浏览器复现：预置“原有记录”，让首次getItem抛错、后续存储恢复；新增“新增记录”后，实际localStorage只剩新记录，原数据保护断言失败。

修复要求：区分无存档和读取失败；失败时禁止写入并提供重读，保留原始数据；损坏存档不能静默覆盖。补读取失败、解析失败、恢复后保留原记录的回归。

## P2：任务返回ID之前停止，停止意图没有发送给新任务

位置：app/frontend/src/lib/generation.ts:92-94；app/frontend/src/pages/Workspace.tsx:303-321。

interrupt立即递增runToken，而start收到创建结果后仅在isCurrent仍成立时发送控制请求。用户在创建请求尚未返回时停止，activeTask为空或仍指向上一任务；新任务ID返回后因为旧token失效跳过控制，服务器任务仍pending。刷新后它可自动续接，和界面“已停止”矛盾。

浏览器模块时序复现：创建请求返回前使当前run失效且control变stopped；调用记录只有POST /api/v1/generation-jobs，没有新任务的/control，保护断言失败。此复现模拟SDK响应时序，没有发出真实云端请求。

修复要求：将停止意图绑定到创建请求/返回任务ID，区分离开页面与显式停止，等待服务器确认后再提示成功。补首次创建、第二次构建、暂停、停止和响应丢失的时序测试。
