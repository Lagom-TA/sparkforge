# 代码审查与修复记录 · 2026-09-09

基线：main / adef01a。用户确认补齐通用交互应用能力，并明确要求不留兼容层。本轮修改保留在本地工作区，未提交、推送或部署。

## 实现结果

- **替换执行契约**：Pydantic 严格模型，runtime 必填，区分 CRUD 与 HTML 两种当前执行能力。单页蓝图不再被强制扩展为两页，也不强制声明数据实体。未知字段、重复 JSON 键、无效引用和显式 null 都不能静默跨过契约。
- **通用应用路径**：HTML AppSpec 定义功能需求，source 阶段由模型输出完整内联 HTML/CSS/经典 JavaScript，预览实际执行生成源码。没有对旧 AppSpec 的适配器、缺省 runtime 或旧任务 404 回退。
- **隔离与状态桥接**：iframe 只授予 allow-scripts；CSP 禁止连接、外部脚本、嵌套框架等资源能力。状态请求验证窗口来源、opaque origin 和每次启动的随机通道。SDK 登录协议的 mgx 消息在 capture 阶段拦截，防止生成页面触发主站的 SDK 消息处理。
- **状态持久化**：新增版本状态 API，校验用户归属、100KB 上限和修订号。服务端锁与修订冲突拒绝并发覆盖；历史版本不能写入。分享演示使用会话内状态，不读取项目保存内容。HTML 下载副本有独立本机存储适配器。
- **修复 CRUD 执行差异**：预览和导出消费实际视图类型、展示列、导航和统计。修复导出 TypeScript 类型错误、数字输入小数限制、同名导出存储碰撞；记录改为稳定 ID 游标分页，不再只拿前 200 条却显示为全部。超过 10000 条预览容量明确报错，不展示不完整统计。
- **防止生成假成功**：源码生成成功后项目状态为 awaiting_verification，功能验收独立保存。用户逐条检查后显式确认，才更新为 ready；确认标注为 owner 验收，不冒充自动测试。
- **错误诊断与重试**：任务记录阶段、次数、错误码和字段路径。只在内部 payload 保存一份有大小上限的失败正文，公开日志和任务快照不返回正文。JSON 错误、契约错误、截断、空响应、HTTP 错误、超时、配置错误分开处理。重试传入校验反馈，截断增加输出预算；普通失败最多三次，配置/过滤/数据冲突不做无效重试。
- **改进迭代上下文与数据完整性**：新构建携带当前应用定义与源码，使后续修改有实际基线。数据写入与发布使用项目锁；发布前检查已有记录能否满足新契约，不转换历史数据，不发布会使已有记录失效的结构。
- **代码质量清理**：开启 TypeScript strict/noImplicitAny/noFallthroughCasesInSwitch；删除无人调用的旧生成/版本写入函数和预留版本号参数；修复 unknown 异常处理；改用 Pydantic ConfigDict；实体接口不再把内部异常正文直接返回给客户端；复制失败不再提示成功。

## 证据边界与后续发布条件

浏览器中的 2048 是具有实际玩法的回归输入，模型适配器测试注入同一输出，证明新契约、生成适配器、隔离执行和状态桥能承载此类应用。**本轮没有调用真实上游模型，不能据此宣称 deepseek 在线生成成功率或任意需求的质量已经通过验收。** 本地浏览器首页的 /api/config 和 /auth/me 代理未连接真实服务，首页截图不构成登录端到端证据。

HTML 运行能力是浏览器前端应用，不是任意全栈项目托管。外部 API、自定义服务器、支付、第三方登录等不在此运行契约内，规划提示词要求明确说明边界。iframe/CSP 也不是具有 CPU/内存配额的独立容器，不能把本轮主站访问与 fetch 隔离测试扩大为所有恶意脚本的资源隔离证明。

发布需要同步前后端和新增数据库结构；旧产物重新生成，不补兼容层。仍需在真实部署完成一轮需求 → 规划 → HTML 生成 → 操作 → 刷新恢复 → 用户验收 → 分享撤销的验证，并核对服务端代码与前端资源版本。此前没有发布本地改动。

沙箱机制参考 [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)；本轮使用 allow-scripts 而不授予 allow-same-origin，存储通过受控桥接完成。
